# tack 1.0 — working plan

Living plan for the 1.0 push. Update it as work lands; a fresh session should be
able to read this and pick up without re-deriving anything.

**Current version:** 0.29.0 · **Spec:** v1 ·
**Route:** `tack` (tacks t24–t30)

## What 1.0 means here

1.0 is a contract promise, not a feature milestone. The spec was already at 100%
coverage when this started; what was missing was a *mechanism* behind the
promise, and the correctness fixes a stable major would otherwise freeze in
place.

Scope was set as **freeze-only**: guardrails, correctness, and a written
compatibility contract.

**Scope widened after the contract landed:** 1.0 now also clears the issue
list — [#14](https://github.com/chris-peterson/tack/issues/14),
[#18](https://github.com/chris-peterson/tack/issues/18), and
[#34](https://github.com/chris-peterson/tack/issues/34) ship in it rather than
after. #18 is the one the freeze actually forces: deriving route status and
flooring `created_at` change what existing fields mean, which `COMPAT-04` makes
a major-version change once 1.0 is out. The other two are additive under
`COMPAT-02` and ride along.

**Cadence:** one PR at a time, stop for review after each.

## Remaining

### t27 — Declare the compatibility contract

In flight on branch `compatibility-contract`. The core 1.0 deliverable: nothing
in the repo stated what a 1.0 freezes.

- New `COMPAT-01..06` category in `spec/v1/SPEC.md` — the frozen surfaces, what
  counts as additive, what is left free to change, what forces a 2.0, the role
  of `spec/v1/cli-usage.txt`, and the one-way direction of file compatibility
  (the schema closes every object, so a release reads what its predecessors
  wrote, never what its successors will).
- Summarized in the root `SPEC.md` and as a README table.
- Two settled decisions written down as requirements: `ROUTE-12` states the slug
  pattern (and that its two-character minimum falls out of the anchored shape),
  `STORE-09` states that a command reading every route fails on the first bad
  file rather than skipping it.

### t31 — `--insert-before` / `--insert-after` for `tack add` (issue #14)

Additive: a new flag pair on an existing command. The interesting part is what
happens to ids — inserting between `t3` and `t4` either renumbers everything
after it (breaking every recorded `depends_on` and every URL a consumer has
kept) or allocates a fresh id and stores position separately.

### t32 — Derived route state (issue #18)

Three changes in one issue: derived route status, a `created_at` floor, and
auto-done-when-the-deliverable-merges. The first two are why this can't wait for
1.1 — they change what a stored field means.

Auto-done needs a forge query, which the Anti-Requirements currently rule out
("core operations never require network access"). Either it becomes an explicit
command the user runs — reconcile-on-demand, not a side effect of `tack status`
— or the anti-requirement changes. Settle the shape before writing code.

### t33 — `tack serve` (issue #34)

The largest item: a loopback HTTP server rendering route/tack/group documents,
OSC 8 hyperlinks from `tack status`, and launchd/systemd user units. beacon's
`serve` is the reference implementation, deliberately, since the two sit side by
side.

Also collides with "No server, sync, or cloud" in the Anti-Requirements. The
distinction that has to be written down: local files stay the only store, and a
read-only loopback renderer is not sync.

### t28 — Cut 1.0.0

Via `/anchor:release`. Note the repo's release workflow delegates to shipyard's
reusable workflow on `release: published`, so the version bump owner needs
confirming before anything is hand-edited.

## Decisions (settled)

1. **Slug minimum length** — keep the two-character minimum. Written down as

   the anchored shape rather than being a rule of its own. Relaxing it later is
   additive under `COMPAT-02`.

2. **Top-level error handler** — added before the freeze (t30, `CLI-55`), since
   it changes the observable output of every error path.

3. **`loadAll()` strictness** — keep fail-outright, written down as `STORE-09`.
   A skipped route is an invisible route.

## Mechanics a fresh session needs

- **Gates** — every one has a `just` recipe and runs in CI; the table in
  `AGENTS.md` says what each catches. `just check` only *previews* generated
  drift (its `--dry-run` exits zero even with drift pending); `just
  check-generated` is the gate.
- **Grammar changes** — re-record with `just usage-snapshot` in the same commit,
  or the snapshot test fails.
- **`dist/` is committed and is what `bin/tack` runs.** Rebuild before
  committing a `src/` change.
- **Sextant skills are not model-invocable.** `/sextant:spec-status` and
  `/sextant:spec-sync` must be typed by the user; `STATUS.md` is written from
  their procedure and should not be hand-edited.
- **Session binding** — `tack session tack <session-id> --tack <tack-id>`.
